## 1. Current SAINT architecture

```
app.py ─ config + logger ─ QLockFile (single instance) ─ first-run check
   │
   ├─ core/module_manager ── enables modules, registers tools (ToolRegistry + permission policy)
   ├─ core/runtime ────────── TTS service, ConversationController, voice start, scheduler, live settings
   └─ ui/main_window ──────── tray, pages (home/music/history/automations/memory/storage/settings),
                               Halo (ui/halo.py), overlay (alt+`), mini player, toasts, action pill

VOICE  modules/voice/module.py  (one audio thread + STT worker threads)
  sounddevice mic (mic_device=2) → 16 kHz, 30 ms frames → 1.5 s pre-roll
  → Silero VAD (+ echo gate against playback level) ─┐
  → openWakeWord-style ONNX "hey_saint" (thr 0.05) ───┤ phases: WAKE → COMMAND(reason) → WAKE/OPEN
  → segmenter (silence 700 ms / 1000 ms in COMMAND, min speech 300 ms, speech ratio ≥ 0.1)
  → faster-whisper base.en (CUDA fp16), stt_filters.clean_transcript
  → wake transcript check / music hot-words / activation gate (_passes_activation_gate)
  → EventType.VOICE_STT_FINAL on core/events bus
CONVERSATION  core/conversation.py → modules/ai (context, Ollama provider) → modules/agent
  agent.handle: confirm/choice resolution → meta → aliases → scenes → learned skills → corrections
             → router.route() (1 600-line deterministic regex router) → tools
             → fallback: agent/llm.py (Ollama /api/chat, llama3.1 8B, tool calling, LLM-exposed tools only)
  → output guard (agent/output.py) → TTS (Kokoro on CUDA, sentence-chunked, barge-in stop)
  → CONVERSATION_TURN_END {expects_reply, was_action} → voice opens the follow-up window
      awaiting reply: 8 s (hard-coded) · follow-up: 15 s (+15 s after an action, max 45 s)
TOOLS / DOMAINS  desktop (apps, windows, UIA, pyautogui/SendInput, Voicemeeter, media WinRT),
  spotify (Web API + PKCE, keyring tokens, poller, memory DB), steam (VDF library, steam:// launch),
  files (scan/junk/archives/recycle), vision (UIA text + optional Ollama vision/FLUX),
  watch (window/screen snapshots every 10 s), notifications (poll every 5 s), learning
  (planner, corrections, skills, demonstration recorder), memory (SQLite, passive learner, profile),
  automation (scheduler, scenes, background tasks), workspace, web search, dev tools
STATE  core/assistant_state (Idle/WakeListening/CommandListening/Processing/Speaking) → ui_link → Halo/overlay
LOGGING  core/logger → data/logs/saint.log (2 MB × 5 rotation); every bus event is logged at INFO
CONFIG  core/config.py defaults ← data/config.json (every key saved; default changes don't reach this user)
PACKAGING  none. run.bat → .venv\Scripts\python app.py; setup.bat builds the venv, installs CUDA torch, pulls llama3.1
```

Strengths worth keeping: deterministic router first with the LLM only as a fallback, a permission policy on
every tool, LLM-exposed allow-list (the shell tool is never exposed), an event bus, a clean phase machine in
voice, a large regression suite, and privacy-conscious logging (passive rejects don't log bystander text).

## 6. One-word response problem

**Where each short word can be lost, in pipeline order:**

| Stage | Behaviour today | Verdict |
|---|---|---|
| Wake phase (no window open) | Only transcripts starting with "SAINT" count, or music hot-words while music plays | **Correct**: a bare "yes" with no context should be ignored |
| **VAD segment validation** | ≥10 voiced frames and ≥10 % voiced ratio over pre-roll + silence padding | **Root cause (B1).** "Yes" = 4–8 frames → dropped silently (event only, no INFO log line) |
| End-of-speech wait | 1 000 ms in every COMMAND window | Makes short answers feel ignored (B2) |
| Awaiting-reply window | 8 s hard-coded, confirmation lives 30 s | Late "yes" is lost (B3) |
| Whisper base.en | Returns conf 0.00–0.2 for single words and mishears some | Weak link (S4) |
| Activation gate | "awaiting reply" is *not* an unaddressed window, so the gate is bypassed. In follow-up windows, a pending confirmation/choice makes `accepts_followup` return True. | **Works** once the audio reaches STT |
| `_CHATTER` regex | "yeah/okay/sure/no" in a *follow-up* window without a pending question → rejected | **Correct** by design |
| `confirm.classify_reply` | yes/no vocab incl. "do it", "go ahead", "cancel", "stop" | Works; lacks "yes please", "go for it", "not yet", "the second one" (choices handle ordinals) |
| LLM-asked questions | `ai.expects_reply` is set when the LLM's reply ends in "?" | Works, but the LLM doesn't know what "yes" confirms unless the question text is in context (it is, via turns) |

**Required state-machine change.** Make the "what is SAINT waiting for" state explicit and single-sourced
instead of inferred from three places (`confirmations.pending`, `choices.pending`, `ai.expects_reply`):

```
DialogState (core/dialog.py, owned by ConversationController)
  IDLE                      – no expectation → bare "yes/no/ok" ignored (need wake word)
  AWAITING_CONFIRM(action)  – yes/no/cancel map to the pending action; TTL = confirm timeout
  AWAITING_CHOICE(options)  – ordinals / names / "the second one"
  AWAITING_SLOT(intent,slot)– "My gym playlist." fills the slot of the previous intent
  AWAITING_OPEN_REPLY(q)    – LLM asked a free question → next utterance goes to LLM with q
  FOLLOW_UP(domain, until)  – after an action: short commands in that domain accepted
```

The voice module reads `DialogState.expects_short_answer` to:
1. relax VAD minimums (≥ 3–4 voiced frames, ratio over the voiced span),
2. shorten end-of-speech to about 500 ms,
3. keep the window open for the whole TTL,
4. bias Whisper with `initial_prompt`/hotwords for the expected vocabulary ("yes no cancel first second …").

With no expectation (IDLE), nothing changes: "yes" still needs "SAINT" first. "Stop / pause / next / back"
stay as music hot-words while media plays. "Stop" while SAINT is speaking is handled by barge-in.

## 7. Game / anti-cheat conflict analysis

**Is SAINT responsible?** The logs have *no* direct evidence of a failed game start caused by SAINT. CS2, Terraria and ROUNDS
launched fine via `steam://`. Apex's problem was the unregistered D: library. Roblox's failure was a Windows shell
cancellation (B9). However, SAINT runs several features that anti-cheat or fullscreen games are known to react to:

| Surface | Present? | Evidence | Risk to games |
|---|---|---|---|
| **Top-most transparent overlay over the game** | **Yes, always** | Halo: 4 `WindowStaysOnTop \| Tool \| TransparentForInput` layered strips per screen, repainted every 33–50 ms; `overlay.halo="always"`; EdgeTab (top-most, *accepts clicks*) polls the cursor every 80 ms | **High.** A topmost, click-through, layered window over a game is the classic ESP-overlay signature that EAC/BattlEye/FACEIT/Vanguard heuristics inspect. It also forces DWM composition, which breaks independent-flip/exclusive fullscreen (FPS and latency cost). The EdgeTab can pop over a game's menu and steal focus on click. |
| **Periodic screen capture** | **Yes, every 10 s** | `modules/watch/snapshots.py:63-67` `ImageGrab.grab` per monitor (GDI BitBlt) whenever the watch module is enabled | **High.** Stutter on capture, and some anti-cheats flag or blacklist processes that capture the game's surface |
| Global hotkey | Yes | `RegisterHotKey(alt+\`)` in `ui/win.py` | Low. It's a documented API, not a hook. |
| Low-level keyboard/mouse hooks | **No** | no `SetWindowsHookEx` / pynput | — |
| Key-state polling | Only while demonstrating | `learning/demonstration.py GetAsyncKeyState` loop | Medium, if a demonstration is left running during a game |
| Injected input | On command | pyautogui, `SendInput`, `keybd_event(ALT)` in `SetForegroundWindow` | Medium. Injected input into a protected game can be flagged. It only happens on command, but hot-words ("louder") use media keys (`pyautogui.press`). |
| DLL injection / process memory access | **No** | no OpenProcess/WriteProcessMemory/CreateRemoteThread in project code | — |
| Process enumeration | Yes | `psutil.process_iter` (window_match, voicemeeter, scheduler) | Low |
| Microphone | Always open while listening | sounddevice stream | None for anti-cheat. It competes only if the game uses an exclusive-mode mic. |
| Virtual audio | Voicemeeter Remote API (user-installed) | `desktop/voicemeeter.py` | Low. Known to coexist with games. |
| GPU contention | Whisper (CUDA) runs on *every* utterance during follow-up windows; Kokoro TTS on CUDA; optional vision on CUDA | logs | Medium. Frame drops during conversation. |
| Processes after exit | Window close = hide to tray (by design). `app.exec()` returns only on tray Quit. No child processes are spawned except user-requested ones. | app.py, runtime.shutdown | Low. Users may *think* SAINT is closed while it's still in the tray. |

**Proposed narrowly scoped solution: Game Mode [P1, M].**

- **Detect** a protected or fullscreen game via the foreground window. The list of processes comes from Steam's library
  (`steam/library.py` already knows install dirs) plus a user list (`game_mode.processes`). Add a fullscreen check
  (`SHQueryUserNotificationState` → `QUNS_RUNNING_D3D_FULL_SCREEN` / `QUNS_BUSY`), which is event-light and needs no capture.
  Use the existing `focus_history` 0.5 s foreground poll; add no new poller.
- **Suspend only these:** Halo and EdgeTab (hide), `watch` screen hashing (window titles are fine), vision capture tools,
  the demonstration recorder, synthetic input into the *game* window (SAINT refuses "click …" while the game is in front
  unless asked by name), and optionally CUDA Whisper → CPU `tiny.en`/`base.en` int8 so the GPU goes to the game.
- **Keep:** wake word, Spotify and media commands (Web API, not keystrokes), Discord/volume via Core Audio (no input
  injection), timers, and TTS (optionally quieter).
- **Indicate:** a tray icon badge, a toast "Game Mode: THE FINALS — overlays off", and the home page status chip.
  Say it once.
- **Restore** when the game process exits (psutil `wait` on that PID in one thread): restore the prior Halo/watch/
  STT settings from a saved snapshot and send a toast.
- **Never** touch Windows Defender, the firewall or the anti-cheat.
- Expose it as "Gaming mode" voice intent (already exists as a scene-like flow in manual tests: "Gaming mode →
  I'm done gaming"). Unify it with this automatic mode.

## 8. EXE / Windows packaging plan

**Today:** `run.bat` → `.venv\Scripts\python.exe app.py`. It needs Python 3.12+ (developed on 3.14), a venv, CUDA
PyTorch (about 3 GB), Kokoro, misaki[en] (spaCy model download at first run), espeak-ng loader, faster-whisper (downloads
its model to the HF cache at first use), onnxruntime, PySide6, pywin32, winrt, pycaw, keyring, and **Ollama as a
separate install** with `llama3.1` pulled. All state is written to `PROJECT_ROOT/data`, so it isn't writable under Program Files.
Smart App Control blocks unsigned SciPy DLLs on this machine (memory note). An unsigned EXE will face the same problem.

**Recommended:** PyInstaller **one-dir** build plus an **Inno Setup** installer (not one-file: torch/CUDA unpacking would take
30+ s per launch and trigger AV heuristics). Nuitka is a later option for startup time.

Before packaging, these must change:
1. **[P1] Split paths.** `core/paths.py`: `resource_path()` (read-only, `sys._MEIPASS` or the repo) versus `data_path()` →
   `%LOCALAPPDATA%\SAINT` when frozen. Migrate `data/` on first run. Fix `LOGO_PATH` (B10) and `data/wake/*.onnx`,
   `data/tts` lookups.
2. **[P1] Model provisioning.** Bundle the wake ONNX. Download Whisper and Kokoro weights on first run with a progress UI
   (existing `core/setup.py` wizard). Detect Ollama and offer its installer link; don't bundle it.
3. **[P1] CUDA variant.** Ship a CPU build (small) and a CUDA add-on, *or* one CUDA build (~3.5 GB). Choose on the installer page.
4. **[P1] AppUserModelID + icon.** `SetCurrentProcessExplicitAppUserModelID("SAINT.Assistant")` before `QApplication`,
   so the taskbar shows SAINT and not python. Pass `.ico` to PyInstaller `--icon` and use `setWindowIcon(QIcon("saint.ico"))`.
5. **[P2] Hidden-import audit.** winrt namespaces, `comtypes` generated code for pycaw/uiautomation, espeakng data,
   misaki/spaCy `en_core_web_sm`, onnxruntime providers, `faster_whisper` assets, and Kokoro voice files.
6. **[P2] Code signing.** Required against Smart App Control and SmartScreen. Budget for an OV/EV cert or Azure Trusted Signing.
7. **[P2] Startup and uninstall.** "Start with Windows" via `HKCU\...\Run` → `SAINT.exe --background`. The uninstaller asks
   whether to keep `%LOCALAPPDATA%\SAINT` and removes the Spotify token from Credential Manager.
8. **[P3] Updates.** Version check against GitHub Releases, and download the installer. No silent self-patching.

## 9. Taskbar icon recommendation

**Analysis of SAINT.png (512², RGBA):** an orange 8-point star with 6 translucent tan "petals" and a
white-ringed black eye. The star fills about 70 % of the canvas. In `TaskbarLogos.png` (the far-right icon) SAINT reads
**smaller and lighter** than its neighbours:
- The **petals** are thin, low-contrast tan ellipses. At 16–20 px they become 1-px smudges that blur the silhouette.
- The **star points** are thin and sharp. At 16 px the 8 points merge into a fuzzy blob.
- **Too much transparent padding.** Windows icons fill about 80–90 % of the frame, so SAINT looks about 20 % smaller than Steam or Discord.
- The **eye** (white ring + black pupil) is the most recognisable element and survives down to 20 px, but at 16 px it's 2–3 px.
- On the **dark taskbar** the orange works. The black pupil vanishes on dark backgrounds without its white ring.
- There is **no .ico**. Qt scales the 512 PNG at runtime, and the taskbar may show python.exe (no AppUserModelID).

**Icon system (preserves identity):**

| Size | Variant | Content |
|---|---|---|
| 256, 48 | **Full** | Current logo, with padding reduced to about 6 %, petals kept but made more opaque |
| 32, 24 | **Simplified** | 8-point star with *thicker, blunter* points; petals removed; eye enlarged to about 38 % of width; ring ≥ 2 px |
| 20, 16 | **Glyph** | 4- or 6-point bold star (or orange disc with star notches) + a single large eye; pixel-hinted; 1 px darker orange outline for light taskbars |
| Tray (16/20/24/32) | **State glyph** | Same glyph; eye/pupil tint reflects state (listening / thinking / speaking / game-mode badge) |

Deliver one multi-resolution `saint.ico` (16, 20, 24, 32, 40, 48, 64, 256; 32-bit alpha), hand-tuned
(not just downscaled) at 16/20/24/32. Plus the tray variants and a Start-menu/`Square150x150` PNG if it's
packaged as MSIX later. Test on dark and light taskbars at 100/125/150 % scaling.

## 16. Dependencies / technical debt

- **Router size:** `modules/agent/router.py` (1 626 lines of regex) plus 10 `*_intents.py` files. It works and is fast, but
  order-dependent. Add a routing-table test that lists every intent against sample phrases (partly exists) before
  adding more patterns. Don't rewrite it.
- **Voice module:** 1 196 lines. The activation logic (gate, hot-words, chatter, fragments) is spread over regexes in the
  class. Move the gate into `voice/activation.py` with pure functions; that makes §6 testable. (Mechanical move.)
- **Three sources of "expects reply"** (confirmations, choices, `ai.expects_reply`) → unify into DialogState (N2).
- **Config shadowing:** every key saved in `data/config.json`, so default changes never reach the user
  (e.g. `hotword_min_confidence` 0.45 vs default 0.2). Add `config_version` migrations for changed defaults
  (the key exists, so extend its use).
- **Heavy deps:** torch/CUDA (~3 GB) only for Kokoro. Kokoro-ONNX via onnxruntime-gpu would remove torch from the
  runtime (big packaging win) [P2, M, needs quality check]. phonemizer + espeakng + misaki + spaCy chain is fragile.
- **Python 3.14** is bleeding-edge for PyInstaller, winrt, pywin32 and CTranslate2 wheels. Consider pinning 3.12/3.13 for release builds.
- **`requirements.txt` has no upper bounds and no lock file.** Add `requirements.lock` (pip-tools) for reproducible builds.
- **Stray `.kilo/worktrees/`** copy of the repo (git-ignored). It confuses searches. The user can delete it if it's not needed.
- **Untracked `CLAUDE.md` and `TaskbarLogos.png`** in the working tree.
